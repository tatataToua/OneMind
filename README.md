# OneMind

[![CI](https://github.com/tatataToua/OneMind/actions/workflows/ci.yml/badge.svg)](https://github.com/tatataToua/OneMind/actions/workflows/ci.yml)

OneMind is a healthcare multi-agent orchestrator. It routes each request to the
specialists that own the relevant data, runs them in parallel, and returns one
cited answer. Personal health information is redacted before any text reaches the
model and restored only in the final response.

By default the system runs locally on `qwen3.5:4b` via [Ollama](https://ollama.com):
no API keys, no network calls, no data leaving the machine. A single environment
variable switches the model to a hosted provider so the system can be deployed
behind a link. The PHI guardrail is what makes that switch acceptable; see
[decision 25](docs/decisions.md) for the argument.

All data in this repository is synthetic. It is generated by
[`backend/fixtures/generate.py`](backend/fixtures/generate.py) from a fixed seed,
and the generator is committed so the claim can be checked. No real patient
information has been used in this project.

## Architecture

```
  request
     │
     ▼
  ┌─────────────────────┐
  │ PHI guardrail (in)  │  identifiers → stable placeholder tokens
  └─────────┬───────────┘
            ▼
  ┌─────────────────────┐
  │ ROUTER              │  which specialists own this? is it answerable?
  └─────────┬───────────┘
            │  not answerable ──────────► one clarifying question
            ▼
  ┌───────────────────────────────────────────────┐
  │ PARALLEL DISPATCH                             │
  │   Clinical      FHIR records                  │   each specialist:
  │   Revenue Cycle claims + ICD-10/CPT           │     plan → call tools
  │   Compliance    policy corpus                 │     → answer from results
  │   Remote Mon.   telemetry time series         │
  │                                               │   two grounding checks:
  │   · a lookup key the request never supplied   │     before the call, and
  │     is dropped, not executed                  │     after the answer
  │   · a claim the tool results do not support   │
  │     is flagged on the answer                  │
  └─────────┬─────────────────────────────────────┘
            ▼
  ┌─────────────────────┐
  │ RECONCILE           │  cross-plane comparisons, computed in code
  │                     │  + harvest identifiers into FACTS
  └─────────┬───────────┘
            │  a blocked specialist that FACTS can unblock
            ├──────────────────────────► second wave (max 2, counted)
            ▼
  ┌─────────────────────┐
  │ SYNTHESIZE          │  merge + attribute  (skipped for a single answer)
  └─────────┬───────────┘
            ▼
  ┌─────────────────────┐
  │ PHI guardrail (out) │  placeholders → real values
  └─────────┬───────────┘
            ▼
      answer + trace + facts
```

The four specialists are separated by the data they can reach, not by topic. Each
owns one source that no other specialist can touch — FHIR documents, coded claim
rows, policy prose, numeric telemetry — and those different shapes are what make
routing decidable. `test_specialists_do_not_share_tools` enforces the separation.

Facts harvested during a turn persist for the length of the conversation, so a
follow-up that names no subject still resolves. Values held between turns are
placeholder tokens, never real identifiers.

The Developer tab in the UI renders this graph from the live span stream: each
stage is highlighted while its spans are open, and a path the request did not
take stays dim.

## Requirements

- [Ollama](https://ollama.com)
- Node 20 or later
- [uv](https://docs.astral.sh/uv/) (or `pip install uv`)

## Quick start

```bash
ollama pull qwen3.5:4b

# terminal 1 — API
cd backend
uv sync --extra dev
uv run uvicorn onemind.api.main:app --port 8080 --reload --reload-include '*.json'

# terminal 2 — UI
cd frontend
npm install
npm run dev            # http://localhost:5173
```

On Windows, `./run.ps1 setup` followed by `./run.ps1 demo` does the same thing.

Before a live demo, start Ollama with the model kept resident so a cold load
cannot happen mid-session:

```
OLLAMA_KEEP_ALIVE=-1      # keep the model in memory
OLLAMA_NUM_PARALLEL=4     # one slot per specialist, so fan-out is real
```

## Tests and evaluation

```bash
cd backend
uv run pytest                              # 402 tests, offline, no model needed
uv run python ../evals/run_eval.py         # routing accuracy, needs Ollama
uv run python ../evals/conversations.py    # memory + two-wave dispatch, needs Ollama
uv run python ../evals/phi_leak.py         # adversarial PHI extraction, needs Ollama
uv run python ../evals/run_eval.py --arm both --repeat 3   # router vs. single-agent baseline
```

The offline test suite and the frontend typecheck run in CI on every push. The
evals are not run in CI: they measure a live 4B model, and their results depend
on the machine they run on. They are run by hand and their reports are committed,
so the numbers below are reproducible.

Multi-turn evaluation, nine scripted conversations against `qwen3.5:4b`: **9/9
pass**, covering two-hop resolution in one turn, follow-ups that name no subject,
subject switching, cross-turn reconciliation, shared-name disambiguation by MRN
and by date of birth, and the cases that must not trigger a second wave.

## Deployment

The hosted build runs on Cloud Run's always-free tier. It tries the deploying
machine's GPU first and falls back to [Groq](https://groq.com) — still an
open-weight Qwen model, so the eval numbers remain comparable — whenever that
machine cannot be reached. The provider is chosen per request, not per deploy
([decision 27](docs/decisions.md)), and `/api/health` reports which provider
actually answered.

```powershell
# backend/.env  (gitignored)
#   ONEMIND_LLM_PROVIDER=groq
#   ONEMIND_GROQ_API_KEY=gsk_...

gcloud init
gcloud services enable run.googleapis.com cloudbuild.googleapis.com `
                       artifactregistry.googleapis.com secretmanager.googleapis.com
./run.ps1 deploy
```

`deploy` stores the key in Secret Manager, grants Cloud Run access to it, and
builds through Cloud Build, so Docker is not required locally. The
[`Dockerfile`](Dockerfile) produces a single image: Node builds the UI, Python
serves both the UI and the API from one origin, which is why production needs no
CORS configuration.

Three deployment flags are deliberate rather than conventional:

- **`--max-instances 1`** — session memory lives in the process
  ([decision 23](docs/decisions.md)). A second instance would strand half the
  conversations and break two-wave dispatch intermittently. This is the
  deployment's real scaling ceiling.
- **`--min-instances 0`** — what keeps the service free. The first request after
  an idle period pays a cold start; load the URL once before demoing.
- **`--region us-central1`** — Cloud Run's free allowance applies only in a few
  US regions.

The model itself is not hosted: GCP's Always Free VM offers 1 GB of RAM against
weights that need roughly four and a half, and the platform has no free GPU.
[Decision 25](docs/decisions.md) works through the alternatives.

### Borrowing a local GPU for a live demo

`./run.ps1 tunnel` points the deployed service at a local Ollama instance for the
length of a walkthrough, through an authenticated Cloudflare tunnel. It warms the
model, starts the gateway, opens the tunnel, verifies that the tunnel answers
with the token and refuses a request without one, redeploys pointed at that
tunnel, and finishes by confirming that Ollama — not the Groq fallback — answered
a real question. `./run.ps1 deploy` returns the service to its resting state.

What the tunnel exposes is [`llm/gateway.py`](backend/src/onemind/llm/gateway.py) —
two routes behind a bearer token — not Ollama, which stays bound to loopback.
Decisions [26](docs/decisions.md) and [27](docs/decisions.md) have the reasoning.

## Security

- PHI is redacted before any text reaches the model and restored only at tool
  calls and in the final answer ([`guardrails/phi.py`](backend/src/onemind/guardrails/phi.py)).
- Retrieved records are treated as untrusted. They are wrapped in a fence that is
  stripped from the payload before the model sees it, and instruction-shaped text
  in a record is surfaced on the trace as an audit signal
  ([`guardrails/injection.py`](backend/src/onemind/guardrails/injection.py)).
- The data plane is committed JSON matched with `==`. There is no query language,
  so there is no SQL injection surface.
- A token-bucket rate limit and a per-caller concurrency cap bound inference
  load ([`api/limits.py`](backend/src/onemind/api/limits.py)).
- `session_id` is a server-minted UUID, validated at the schema boundary.

Authentication, authorisation, distributed rate limiting, and encryption at rest
are out of scope, with reasons. The full threat model — what the system defends
against, what it does not, and why — is in [`SECURITY.md`](SECURITY.md), and is
tested in `backend/tests/test_security.py`.
