# OneMind

A healthcare multi-agent orchestrator. It routes a request to the specialists
that own the relevant data, runs them in parallel, and returns one cited answer
— with PHI redacted before any of it reaches the model.

Everything runs locally on `qwen3.5:4b` via Ollama. No API keys, no network
calls, no data leaving the machine.

> **All data in this repository is synthetic**, generated by
> `backend/fixtures/generate.py` from a fixed seed. No real patient information
> has ever been near this project. The generator is committed so that claim is
> checkable rather than asserted.

---

## The idea in one picture

```
  request
     │
     ▼
  ┌─────────────────────┐
  │ PHI guardrail (in)  │  identifiers → stable placeholder tokens
  └─────────┬───────────┘
            ▼
  ┌─────────────────────┐
  │ ROUTER              │  which specialists own this? is it answerable?
  └─────────┬───────────┘
            │  not answerable ──────────► one clarifying question
            ▼
  ┌───────────────────────────────────────────────┐
  │ PARALLEL DISPATCH                             │
  │   Clinical      FHIR records                  │   each specialist:
  │   Revenue Cycle claims + ICD-10/CPT           │     plan → call tools
  │   Compliance    policy corpus                 │     → answer from results
  │   Remote Mon.   telemetry time series         │
  └─────────┬─────────────────────────────────────┘
            ▼
  ┌─────────────────────┐
  │ SYNTHESIZE          │  merge + attribute  (skipped for a single answer)
  └─────────┬───────────┘
            ▼
  ┌─────────────────────┐
  │ PHI guardrail (out) │  placeholders → real values
  └─────────┬───────────┘
            ▼
      answer + trace
```

The four specialists are split by **what data they can reach**, not by topic.
Each owns one source no other can touch, and the four sources have deliberately
different shapes — documents, coded rows, prose, numeric series. That is what
makes routing decidable; `test_specialists_do_not_share_tools` enforces it.

## Quick start

Prerequisites: [Ollama](https://ollama.com), Node 20+, and
[uv](https://docs.astral.sh/uv/) (or `pip install uv`).

```bash
ollama pull qwen3.5:4b

# terminal 1 — API
cd backend
uv sync --extra dev
uv run uvicorn onemind.api.main:app --port 8080 --reload --reload-include '*.json'

# terminal 2 — UI
cd frontend
npm install
npm run dev            # http://localhost:5173
```

On Windows, `./run.ps1 setup` then `./run.ps1 demo` does the same thing.

### Keep the model warm before a live demo

A cold model load mid-demo is the worst failure mode. Set these before starting
Ollama:

```
OLLAMA_KEEP_ALIVE=-1      # keep the model resident
OLLAMA_NUM_PARALLEL=4     # one slot per specialist, so fan-out is real
```

## Verify it works

```bash
cd backend
uv run pytest                          # 45 tests, offline, no model needed
uv run python ../evals/run_eval.py     # routing accuracy, needs Ollama
```

Latest evaluation, 102 labelled prompts against `qwen3.5:4b`:

| metric | result |
|---|---|
| single-agent accuracy | **98.8%** |
| multi-agent exact match | 91.7% |
| abstain accuracy (vague prompts refused) | 90.0% |
| overall exact match | 97.1% |
| label precision / recall | 97.2% / 99.0% |
| router latency | p50 1776 ms, p95 2103 ms |

Precision and recall are reported separately because their costs differ. Missing
a specialist yields an incomplete answer; waking a spare one costs a few seconds
and some noise.

## Adding a specialist

One `SpecialistSpec` in `backend/src/onemind/agents/catalog.py` and a tool
module. The router builds its prompt from the registry and the constrained
decode is generated from the live roster, so a new key is routable immediately.
The UI reads `/api/agents`, so its rail updates too. No other file changes.

## Demo script

1. **Clinical** — single agent, one FHIR lookup.
2. **Cross-agent: clinical + billing** — two agents start ~2 ms apart; watch the
   trace bars overlap.
3. **Ambiguous** (`check the numbers`) — refused with one clarifying question
   rather than a guess.
4. **PHI redaction** — click the *N PHI redacted* pill to see exactly what the
   model received.
5. `uv run python ../evals/run_eval.py` — the numbers above, live.
6. If asked how it scales: add a fifth specialist to the registry.

Expect roughly 4 s for a single-agent answer and 9–14 s for a cross-agent one on
an RTX 3060 Ti.

## Architecture notes

**Provider seam.** `LLMProvider` is three methods. Router, specialists, and
synthesiser are written against it and know nothing about Ollama or HTTP.
`ONEMIND_LLM_PROVIDER=bedrock` switches the whole system to Claude on Bedrock.

**Structured output.** Routing and tool-argument selection use JSON Schema
enforced *during decoding* (`format` on Ollama; forced tool-use on Bedrock), so
malformed routing output is unrepresentable rather than merely unlikely.

**Arithmetic lives in tools.** Means, trends, breach runs, and denial rates are
computed in Python. The model interprets numbers; it does not produce them.

**Traces are audit records.** Spans carry redacted text only, per the rule in
`fixtures/policies/access-control-and-audit.md` that audit logs reference
records by identifier and never by content.

## Configuration

All settings take an `ONEMIND_` prefix.

| Variable | Default | Notes |
|---|---|---|
| `ONEMIND_LLM_PROVIDER` | `ollama` | or `bedrock` |
| `ONEMIND_OLLAMA_MODEL` | `qwen3.5:4b` | raise on a larger GPU |
| `ONEMIND_OLLAMA_NUM_CTX` | `16384` | capped well below the 256K ceiling to fit four slots in 8 GB |
| `ONEMIND_MAX_PARALLEL_AGENTS` | `4` | match `OLLAMA_NUM_PARALLEL` |
| `ONEMIND_PHI_REDACTION_ENABLED` | `true` | turn off only to demonstrate the difference |
| `ONEMIND_BEDROCK_MODEL_ID` | Claude 3.5 Sonnet | requires `boto3` |

## Known limits

Stated plainly, because a reviewer will find them anyway.

- **PHI detection is pattern-based** plus a roster of known names from the
  fixtures. Right shape for the trust boundary, wrong tool for open-world text.
  Production would put Presidio or Comprehend Medical behind the same interface.
- **A 4B model over-reports disagreement.** When one specialist has no data on a
  topic, the synthesiser sometimes frames that gap as a contradiction despite an
  explicit instruction not to. The prompt mitigates it; a larger model removes
  it.
- **Retrieval is lexical, not dense.** Deliberate at six documents — see
  [decisions.md](docs/decisions.md#14-policy-retrieval-returns-five-sections-not-three).
- **No persistence.** Every request is stateless; there is no conversation
  memory. Follow-up questions must restate their subject.
